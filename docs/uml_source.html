3. Class Diagram — Orchestration, Agents & Tools

ProjectRun depends on the Developer/Reviewer protocols; the concrete agents wrap an LLMClient and a role-specific toolset. Tool access is enforced by which methods each toolset exposes.

classDiagram
  direction LR
  class ProjectRun {
    +state: ProjectState
    +developer: Developer
    +reviewer: Reviewer
    +ui: ConsoleUI
    +log: RunLog
    +max_iterations: int = 5
    +execute() ProjectState
    -_run()
    -_validate() ValidationReport
    -_review(validation) Review
    -_work_from(review, validation) list~str~
    -_final_acceptance(review, validation) str
    -_sync_dependencies()
    -_checkpoint(label)
    -_close()
    -_approver(agent) Approve
    -_reporter(agent) Callable
  }
  class Developer {
    <<Protocol>>
    +implement(message, approve, on_call) ToolLoopResult
    +adjudicate(message, review, human_decisions) DeveloperResponse
  }
  class Reviewer {
    <<Protocol>>
    +investigate(message, approve, on_call) ToolLoopResult
    +review(message, specification, changes_made) Review
  }
  class DeveloperAgent {
    +llm: LLMClient
    +tools: DeveloperToolset
    +implement(message, approve, on_call) ToolLoopResult
    +adjudicate(message, review, decisions) DeveloperResponse
  }
  class ReviewerAgent {
    +llm: LLMClient
    +tools: ReviewerToolset
    +investigate(message, approve, on_call) ToolLoopResult
    +review(message, specification, changes_made) Review
  }
  class SpecificationBuilder {
    +llm: LLMClient
    +build(user_prompt) Specification
    -_validate_specification(spec, prompt)
  }
  class LLMClient {
    +model: str
    +base_url: str

    +chat(messages, schema, temperature) str
    +complete(messages, tools, temperature) dict
    -_send(payload) dict
  }
  class ReadOnlyToolset {
    +base: str
    +list_files() list~str~

    +write_file(relative_path, content) str

6. Sequence Diagram — Startup & Specification Agreement

main() refuses to start on a dirty repo, agrees a specification with the human, then hands a fresh ProjectState to ProjectRun.

sequenceDiagram
  autonumber
  actor H as Human
  participant M as main()
  participant UI as ConsoleUI
  participant G as tools.git
  participant SB as SpecificationBuilder
  participant RA as ReviewerAgent
  participant PD as project_doc
  participant L as LLMClient
  participant S as llama-server
  participant RL as RunLog
  participant PR as ProjectRun

  M->>G: status()
  alt uncommitted changes
    M->>UI: say("Commit or stash them first")
    M-->>H: exit
  end
  M->>G: current_branch(), current_commit()
  M->>PD: load_document(), changes_since(document)
  alt document describes HEAD
    PD-->>M: stored summary + history
  else project has code (no document, or code changed since)
    M->>UI: confirm("Let the Reviewer read the project first?")
    H->>UI: yes
    M->>RA: survey_project: investigate(survey task)
    M->>RA: summarize(notes) - only real file paths accepted
    RA-->>M: ProjectSummary
  end
  M->>UI: ask_required("Enter a simple software request")
  H->>UI: request text
  loop until approved or rejected
    M->>SB: build(user_request, context=summary + history)
    loop up to 3 attempts
      SB->>L: chat(messages, schema=Specification, temperature=0)
      L->>S: POST /chat/completions
      S-->>L: JSON content
      L-->>SB: content
      SB->>SB: model_validate_json + _validate_specification<br/>(unique IDs, source_text verbatim in prompt)
    end
    SB-->>M: Specification
    M->>UI: show spec, choose [Y]es / [N]o / [R]egenerate
    H->>UI: choice
  end
  alt rejected
    M-->>H: "Stopping before implementation"
  else approved
    M->>M: ProjectState(run_id, spec, base_commit, run_branch=sol/run-id)
    M->>RL: save_state(state), event("specification_approved")
    M->>M: create review_dir (temp), DeveloperAgent(DeveloperToolset), ReviewerAgent(ReviewerToolset)
    M->>PR: execute()
    PR-->>M: final ProjectState
    M->>M: remove review_dir
  end

7. Sequence Diagram — Agent Tool Loop (run_tool_loop)

Shared by Developer.implement and Reviewer.investigate. max_steps = 20 (Developer) or 15 (Reviewer). Tools in NEEDS_APPROVAL require the human's consent first.

sequenceDiagram
  autonumber
  participant A as Agent (Developer / Reviewer)
  participant TL as run_tool_loop
  participant L as LLMClient
  participant S as llama-server
  participant D as dispatch()
  participant AP as approve() — ProjectRun._approver
  actor H as Human
  participant T as Toolset
  participant R as on_call — ProjectRun._reporter

  A->>TL: run_tool_loop(llm, toolset, system_prompt, message, approve)
  TL->>TL: specs = tool_specs_for(toolset)
  loop up to max_steps
    TL->>L: complete(messages, tools=specs)
    L->>S: POST /chat/completions
    S-->>L: assistant message
    L-->>TL: reply
    alt no tool_calls
      TL-->>A: ToolLoopResult(final_text, calls)
    else tool_calls requested
      loop each tool call
        TL->>D: dispatch(toolset, name, raw_args, approve)
        D->>D: lookup spec, parse JSON, check arguments
        opt name in {run_tests, run_review_tests, install_dependencies}
          D->>AP: approve(name, args)
          AP->>H: confirm("…executes code inside the Docker sandbox. Allow?")
          H-->>AP: y / n
          AP-->>D: allowed
        end
        alt allowed and valid
          D->>T: method(**arguments)
          T-->>D: str / GitResult / SuiteRun / list
          D->>D: _format(result)
        else error / declined
          D->>D: "ERROR: …"
        end
        D-->>TL: result text
        TL->>R: on_call(ToolCall) — print + log event
        TL->>TL: append {role: tool, content: result}
      end
    end
  end
  TL-->>A: raise ToolLoopLimitError

8. Sequence Diagram — Structured Output with Retry (request_structured)

Used by DeveloperAgent.adjudicate (→ DeveloperResponse) and ReviewerAgent.review (→ Review). The exact rejection reason is fed back to the model.

sequenceDiagram
  autonumber
  participant A as Agent
  participant RS as request_structured
  participant L as LLMClient
  participant P as Pydantic model
  participant V as validator<br/>(validate_review / validate_developer_response)

  A->>RS: request_structured(llm, prompt, message, Model, validate, Rejection, what)
  loop attempt 1..3
    RS->>L: chat(messages + retry note, schema=Model.json_schema, temperature=0)
    L-->>RS: JSON text
    RS->>P: model_validate_json(text)
    alt schema invalid
      P-->>RS: ValidationError
      RS->>RS: last_error = error
    else schema ok
      RS->>V: validate(result)
      alt business rule broken
        V-->>RS: ReviewRejected / ResponseRejected
        RS->>RS: last_error = error
      else ok
        RS-->>A: result
      end
    end
  end
  RS-->>A: raise StructuredOutputError(last_error)

9. Sequence Diagram — One Review Iteration

Orchestrator-run validation, adversarial review, the human's ruling on findings, Developer adjudication, dispute resolution and the fix pass with a git checkpoint.

sequenceDiagram
  autonumber
  actor H as Human
  participant PR as ProjectRun
  participant V as validation
  participant DK as Docker sandbox
  participant RA as ReviewerAgent
  participant DA as DeveloperAgent
  participant G as tools.git
  participant RL as RunLog

  PR->>PR: _sync_dependencies() (ask H before install)
  PR->>V: run_validation(base, approve_tests)
  V->>V: check_syntax(), check_dependencies()
  V->>H: "Import the modules and run the tests?" (asked once)
  H-->>V: yes
  V->>DK: docker run --network none --read-only … import each module, then pytest
  DK-->>V: SuiteRun
  V-->>PR: ValidationReport
  PR->>G: diff(base_commit)
  PR->>RA: investigate(message with diff + validation)
  Note over RA: tool loop: read files,<br/>write_review_test, run_review_tests
  RA-->>PR: ToolLoopResult (notes + transcript)
  PR->>RA: review(message, spec, changes_made)
  RA-->>PR: Review (verdict, requirement results, findings)
  PR->>RL: save_state, event("review")
  PR->>PR: blocking_problems(review, validation)
  alt no blocking problems
    PR->>H: FINAL REVIEW: [a]ccept / [t]ry / [f]eedback / [p]ick / [i]terate / [s]top
    Note over PR,H: feedback: bug/change becomes H-nnn, feature amends spec.<br/>pick: improvement becomes S-nnn, addition amends spec.<br/>H-/S- items skip human_review and go straight to adjudication.
  else blocking problems
    PR->>H: list problems (ask to continue if iteration limit hit)
  end
  opt review has findings
    PR->>H: human_review(): approve / reject / investigate / instruct each
    H-->>PR: list~HumanDecision~
    PR->>DA: adjudicate(message, review, decisions)
    DA-->>PR: DeveloperResponse (accept / partially_accept / reject)
    PR->>H: resolve_disputes(): uphold or override each rejection
    H-->>PR: overridden ids, dismissed findings
  end
  PR->>DA: implement(fix message with work items)
  Note over DA: tool loop: read_file, write_file,<br/>run_tests, git_diff
  DA-->>PR: ToolLoopResult (summary)
  PR->>G: commit_all("sol: fix N (run id)")
  G-->>PR: commit sha
  PR->>RL: event("checkpoint")

10. Activity Diagram — ProjectRun.execute()

Main control flow. Any exception sets status = failed; _close() always runs (final commit, switch back to original branch, optional fast-forward merge).

flowchart TD
  start((●)) --> B[create_branch sol/run-id]
  B --> I[Developer.implement spec]
  I --> C1[checkpoint: implementation]
  C1 --> IT[iteration += 1]
  IT --> DEP{pending packages?}
  DEP -- yes --> ASKD{human approves install?}
  ASKD -- yes --> INS[install_dependencies]
  ASKD -- no --> VAL
  INS --> VAL
  DEP -- no --> VAL[run_validation<br/>syntax · deps · imports · tests · deleted files]
  VAL --> REV[Reviewer.investigate → Reviewer.review]
  REV --> BP{blocking problems?}
  BP -- no --> FIN{final review choice}
  FIN -- try --> TRY[try_program, offer restore] --> FIN
  FIN -- accept --> OK[status = complete]
  FIN -- stop --> FAIL[status = failed]
  FIN -- iterate --> WORK
  FIN -- feedback --> FB[bug or change: queue H-finding<br/>feature: amend spec, human approves]
  FIN -- pick --> PK[improvement: queue S-finding<br/>addition: amend spec, human approves]
  FB --> WORK
  PK --> WORK
  BP -- yes --> LIM{iteration ≥ max<br/>and human declines more?}
  LIM -- yes --> FAIL
  LIM -- no --> WORK[collect work: failed requirements,<br/>validation failures]
  WORK --> FND{review has findings?}
  FND -- yes --> HR[human_review each finding]
  HR --> ADJ{findings to adjudicate?}
  ADJ -- yes --> DR[Developer.adjudicate → resolve_disputes]
  DR --> ADDW[add accepted + overridden findings to work]
  ADJ -- no --> EMP
  ADDW --> EMP
  FND -- no --> EMP{work empty?}
  EMP -- yes --> IT
  EMP -- no --> FIX[Developer.implement fix message]
  FIX --> C2[checkpoint: fix N]
  C2 --> IT
  OK --> DOC[Reviewer.summarize: write .sol project<br/>document, commit it]
  DOC --> CL
  FAIL --> CL[_close: commit leftovers,<br/>switch to original branch]
  CL --> MQ{complete and checkpoints<br/>and human agrees?}
  MQ -- yes --> MG[merge_fast_forward run branch]
  MQ -- no --> E((◉))
  MG --> E

11. State Machine — ProjectState.status

Values of the Status literal in schemas/state.py and the transitions ProjectRun makes. "test" is declared but not currently entered.

stateDiagram-v2
  [*] --> requirements : ProjectState created
  requirements --> implement : execute()
  implement --> validate : implementation checkpoint
  validate --> review : ValidationReport saved
  review --> final_review : no blocking problems
  review --> human_review : blocking problems, findings exist
  review --> fix : blocking problems, no findings
  review --> validate : nothing to fix (re-review)
  review --> failed : iteration limit, human stops
  final_review --> complete : accept
  final_review --> failed : stop
  final_review --> human_review : iterate on optional findings
  final_review --> developer_response : feedback / adopted suggestions
  final_review --> fix : new requirements only
  human_review --> developer_response : findings to adjudicate
  human_review --> fix : work items, none to adjudicate
  human_review --> validate : no work
  developer_response --> fix : work items
  developer_response --> validate : no work
  fix --> validate : fix checkpoint
  test : test (declared, unused)
  complete --> [*]
  failed --> [*]
  note left of failed
    also entered on any
    exception in execute()
  end note

Runtime nodes. The model server is local (default http://localhost:8080/v1). Tests run in a locked-down container unless SANDBOX=local; "try it yourself" runs on the host by design.
